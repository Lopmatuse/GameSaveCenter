# Windows 真机验证计划

每项结果记录为：`通过 / 失败 / 跳过`，并保存错误日志。不要在同一轮同时开启本地备份、恢复和云端双向行为。

## A. 构建门禁

- [ ] `dotnet --info` 显示 .NET 8 或更高版本的稳定版 SDK（.NET 9 可用）。
- [ ] `dotnet restore GameSaveCenter.sln` 成功。
- [ ] `dotnet build GameSaveCenter.sln -c Release` 无错误。
- [ ] `dotnet test tests/GameSaveCenter.Core.Tests -c Release` 全部通过。
- [ ] `scripts/package.ps1` 生成 Worker 与扩展目录。
- [ ] Playnite 启动后插件无加载错误。

## B. 基础 IPC 与配置

- [ ] Worker 只启动一个实例。
- [ ] 命名管道 Ping 成功。
- [ ] 设置保存后重启 Playnite仍然存在。
- [ ] Worker 数据库位于 `%LOCALAPPDATA%\GameSaveCenter`。
- [ ] 日志中没有 Token、密码或完整 Rclone 配置内容。

## C. 游戏库与启动方式

至少测试：

- [ ] Steam 普通启动；
- [ ] Xbox/Game Pass 普通启动；
- [ ] Epic/Ubisoft/EA/GOG 中实际使用的平台；
- [ ] Playnite Game Action 启动；
- [ ] 直接从平台客户端启动；
- [ ] 一个 MOD loader（例如 SKSE/SMAPI/MO2/Mod Engine）；
- [ ] loader 退出但游戏继续运行时，会话不应提前结束；
- [ ] 同一游戏不会同时出现两个逻辑会话。

## D. Ludusavi 备份

选择一个可丢弃测试存档：

- [ ] 游戏匹配名称正确；
- [ ] 手动单游戏备份成功；
- [ ] 全部备份不会处理未匹配游戏；
- [ ] 游戏退出后生成最终备份任务；
- [ ] 游玩超过配置间隔后生成定时备份；
- [ ] 没有变化时 Ludusavi 行为符合预期；
- [ ] 备份历史、文件数、大小和备注可见；
- [ ] 锁定状态在 Ludusavi 中真实生效；
- [ ] 体积/文件数异常会产生 finding。

## E. 媒体增量同步

- [ ] Steam F12 截图归类到正确 AppID 游戏；
- [ ] 重复运行同步不会再次复制相同文件；
- [ ] 同图改名仍由 SHA-256 去重；
- [ ] Xbox Game Bar 截图正确归类或进入待人工处理；
- [ ] Epic/Ubisoft/EA/GOG 的自定义目录生效；
- [ ] `*.png` 等匹配模式生效；
- [ ] 共享目录不会把明显属于其他游戏的文件归入当前游戏；
- [ ] 错误归类可在 UI 重新分配；
- [ ] 删除源截图不会删除归档副本；
- [ ] 正在写入的视频不会复制半成品。

## F. Rclone 单向云端复制

使用测试 Remote 和空目录：

- [ ] 初始全局云端开关关闭时不会上传；
- [ ] 开启后只调用 `copy`，不调用 `sync/delete/purge`；
- [ ] 本地断网时本地备份仍成功，云任务失败可见；
- [ ] 恢复网络后重新复制成功；
- [ ] `rclone check --one-way` 可验证测试目录；
- [ ] 删除本地测试副本不会自动删除云端文件；
- [ ] 多电脑使用不同 `<MachineName>` 子目录。

## G. 安全恢复

只测试可完全丢弃的存档：

- [ ] 游戏、平台客户端写盘进程和 MOD manager 已关闭；
- [ ] 恢复前创建新的 PreRestore；
- [ ] PreRestore 有备注并锁定；
- [ ] 预览失败时不写入真实存档；
- [ ] 指定历史版本恢复成功；
- [ ] 恢复后游戏能够读取；
- [ ] 撤销恢复回到 PreRestore；
- [ ] 人为制造失败时回滚路径可用；
- [ ] 恢复过程中没有云端任务覆盖本地。

## H. 自动识别与 WGS

- [ ] 候选扫描不会无界扫描整盘；
- [ ] 缓存、日志、shader、截图目录被降权；

- [ ] Xbox WGS 只在确认映射后备份；
- [ ] 首轮不执行 Xbox WGS 覆盖恢复。

## 0.2.0 缺陷回归门禁

### A. 设置持久化与刷新

1. 在设置页填写 Ludusavi 路径并保存。
2. 完全退出 Playnite，终止 Worker，再重新打开 Playnite。
3. 确认底栏显示实际 Ludusavi 版本，测试游戏不需要 PowerShell 注入即可“已就绪”。
4. 点击刷新，确认游戏数、匹配数和当前选择不丢失。
5. 检查 `%LOCALAPPDATA%\GameSaveCenter\worker-settings.json`，确认非敏感路径和策略已保存。

### B. ZIP 多版本

1. 使用 `GameSaveCenter Test`，源文件依次写入 `version=1`、`version=2`、`version=3`。
2. 每次变化后点击立即备份。
3. 历史应出现至少三个不同 BackupId；刷新和重启后仍存在。
4. 任务详情分别显示首个版本/新的历史版本，不得显示 `LUDUSAVI_NOT_CONFIGURED`。
5. 再次备份未变化文件，任务应成功并提示“存档无变化，历史未新增”。

### C. 时间与错误详情

1. 任务、历史、媒体、审计时间应与 Windows 当前本地时间一致。
2. 临时把 Ludusavi 路径改成不存在的文件并保存，执行备份。
3. 任务详情应显示 `LUDUSAVI_NOT_CONFIGURED` 和明确说明；恢复正确路径后刷新应自动恢复匹配。

### D. 历史刷新与恢复

1. 选中一个历史版本后点击刷新，当前游戏历史不得清空。
2. 只对可丢弃测试存档执行安全恢复。
3. 确认恢复前生成锁定的 PreRestore，恢复后文件内容正确，撤销恢复可回到原状态。

### E. UI 视觉回归

分别测试 Playnite 浅色、深色和至少一个第三方主题：

- 标题、标签、禁用按钮、表格文字均清晰；
- 卡片、按钮、输入框和选中状态保持圆角与弱边框；
- 不出现硬编码黑字压在深色背景上的情况；
- 100%、125%、150% 缩放下不截断主要操作；
- 插件内不绘制 macOS 红黄绿窗口按钮。

## 0.4.0 主题模式、会话候选与任务重试回归

### A. 版本和设计资源

1. 双击 `GameSaveCenter-Run.cmd`，安装报告必须显示清单 `0.4.0`、DLL `0.4.0.0`。
2. 安装目录必须包含 `Themes/DesignTokens.xaml`，管理面板与设置页均能打开。
3. `python scripts/validate-source.py` 应通过，且 UI 改动已阅读 `docs/design/APPLE_WPF_IMPLEMENTATION_PROMPT.md` 与 `UI_CHANGE_GATE.md`。

### B. 三种主题模式

1. 选择“跟随 Playnite”，分别在默认深色、默认浅色和第三方主题打开管理面板。
2. 选择“浅色”并保存，不重启 Playnite，重新打开或切回面板后局部 UI 应保持稳定浅色且文字清晰。
3. 选择“深色”并保存，验证同样的即时重算与重启持久化。
4. 三种模式下检查输入框、ComboBox 下拉项、禁用按钮、任务表格、候选表格和侧栏状态。
5. 高对比度或关闭毛玻璃时，固定主题不得导致透明文字、黑块或丢失键盘焦点。

### C. 会话前后存档候选

1. 准备一个尚未匹配 Ludusavi 的可丢弃测试游戏，并开启“会话存档路径检测”。
2. 启动游戏后等待 1–2 分钟，创建或修改测试存档，然后正常退出。
3. 打开该游戏的“候选存档路径”，应出现包含“会话前后快照发现新增/修改”理由的候选。
4. 候选必须显示可信度、状态、路径和完整判断依据；长路径使用 Tooltip。
5. 点击“忽略候选”，切换游戏、刷新、重启 Worker 后状态仍为“已忽略”。
6. 再选择另一候选点击“接受并生成规则草案”，状态应为“已接受”，后续扫描不得重新插入同一路径为 Pending。
7. 已匹配 Ludusavi 的游戏启动时不得执行大范围候选快照。
8. 强制结束 Worker 后重新启动，超过两天的测试快照应被清理；当前有效候选不得丢失。

### D. 任务复制与安全重试

1. 制造一个可恢复的 Backup 失败任务，选中后“复制详情”应包含游戏、任务类型、真实错误和任务 ID。
2. 修正失败原因后点击“安全重试”，应新建任务并完成备份，不修改原任务历史。
3. 对 MediaSync 的 Failed/Cancelled 任务重复测试。
4. 对 Restore、UndoRestore 或未知任务类型，“安全重试”必须禁用。
5. Running/Queued 任务仍使用取消按钮，Succeeded 任务的取消和重试均禁用。

### E. Game Bar / Windows 公共媒体会话归类

1. 使用文件名不包含游戏名的测试截图，在单一游戏会话期间生成，退出后触发媒体同步。
2. 截图时间落在会话开始前 2 分钟至结束后 10 分钟时，应归类到本次游戏。
3. 同时保持另一游戏会话运行，重复生成截图；时间推断应自动关闭，除非文件名明确匹配，否则不得误归类。
4. 手动“同步媒体”没有 SessionId 时仍只使用文件名/明确来源，不得仅凭最近时间归类。
5. 验证已归档媒体 SHA-256 去重仍有效，源文件删除不会删除归档。


## 0.4.1 全局媒体收件箱回归

### A. 构建、安装与旧库升级

1. 双击 `GameSaveCenter-Run.cmd`，安装报告必须显示清单 `0.4.2`、DLL `0.4.2.0`。
2. 使用保留 0.4.0 `state.db` 的环境启动 Worker；不得出现 `classification_state`、`classification_reason` 或 `ix_media_classification` 迁移错误。
3. 重启 Worker 两次，迁移必须幂等，既有已归类媒体仍显示在原游戏下。
4. `python scripts/validate-source.py`、真实 `dotnet build/test`、PEXT 打包与 Playnite 加载全部通过。

### B. 歧义媒体进入收件箱

1. 准备一个文件名不包含任何游戏名的测试截图，放入 Game Bar Captures、Windows Screenshots 或标记为“共享目录”的自定义来源。
2. 在没有 SessionId 的手动媒体同步中，文件必须复制到媒体库 `_Inbox/Pending` 并显示在“待归类媒体收件箱”。
3. 列表应显示拍摄时间、类型、来源、文件名、大小和无法归类原因；源文件仍在原目录。
4. 文件名同时匹配两款游戏时，原因应明确提示多游戏歧义，不得自动选择其中之一。
5. 首次面对超过 200 个歧义历史文件时，一轮最多新增 200 个；再次同步应跳过已导入哈希并继续补齐更旧项目。

### C. 保守自动归类

1. 文件名只明确匹配一款游戏时，应直接进入该游戏媒体目录，不进入收件箱。
2. 文件名不匹配，但带明确 SessionId、时间位于开始前 2 分钟至结束后 10 分钟且无其他游戏会话重叠时，应按会话归类。
3. 存在重叠游戏会话时，时间推断必须关闭；无法唯一文件名匹配的项目进入收件箱。
4. 同一路径被系统来源和共享自定义来源同时发现时，只归档一次。

### D. 人工归类与忽略

1. 在收件箱选择媒体与目标游戏，点击“确认归类”；归档文件应移动到目标游戏的 Screenshots/Clips 年月目录，SQLite 状态变为 `Assigned`，收件箱立即移除。
2. 目标路径已存在相同 SHA-256 时可安全复用；存在不同内容时必须停止并报错，禁止覆盖。
3. 将 Pending 归档副本临时移走但保留原始截图，再执行归类；程序应重新复制归档，原始截图不能被移动或删除。
4. 点击“忽略并保留副本”，文件应移动到 `_Inbox/Ignored`，状态为 `Ignored`，不再出现在收件箱；原始文件和忽略归档均保留。
5. 关闭管理面板、刷新、重启 Playnite/Worker 后，Assigned/Inbox/Ignored 状态与路径保持一致，审计日志可追踪人工操作。

### E. 任务、主题与性能

1. 制造 `MediaInbox` Failed/Cancelled 任务，“安全重试”应只扫描共享来源，不为每个游戏创建专属媒体任务。
2. 在约 965 款游戏库中打开截图与录像页，目标游戏下拉可用，切换筛选不影响全局收件箱选择和计数。
3. 默认深色、默认浅色、至少两个第三方主题以及 100%、125%、150%、200% DPI 下，表格、长文件名、空状态和按钮无裁剪、黑块或低对比。
4. 使用大目录观察 CPU、磁盘和 UI 响应；扫描运行在 Worker，Playnite UI 不得卡死，取消与真实任务状态应保持可用。
## 0.4.2 Playnite 侧栏崩溃热修复回归

1. 关闭 Playnite，使用全新 0.4.2 源码执行 `GameSaveCenter-Run.cmd`，构建、测试、打包和安装必须全部成功。
2. 在附加组件页确认 GameSaveCenter 显示 `0.4.2`，不要继续测试仍显示 `0.4.1` 的安装。

3. 点击 GameSaveCenter 侧栏，必须成功创建 Dashboard；不得出现扩展崩溃窗口、`XamlParseException` 或找不到 `GscStatusPill`。
4. 连续关闭并重新打开侧栏至少 5 次，依次切换概览、游戏、备份、任务、截图与录像、诊断和异常日志标签。
5. 打开截图与录像页，待归类数量胶囊应具有玻璃背景和细边框；不存在透明空块、缺失边框或资源警告。
6. 分别切换跟随 Playnite、固定浅色、固定深色；关闭并重开侧栏后资源仍能解析。
7. 检查 `playnite.log` 与 `extensions.log`，本轮不得新增 GameSaveCenter XAML 资源解析异常。

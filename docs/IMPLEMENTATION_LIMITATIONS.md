# 已知限制与风险

## 1. 当前未在 Windows 编译

当前执行容器没有 .NET SDK、MSBuild、Playnite 和 Windows API。尝试下载临时 SDK 时被环境的网络/文件策略阻止。因此：

- 已执行源码结构、XAML/XML、JSON/YAML、解决方案、IPC 常量和 C# 括号检查；
- 已编写 xUnit 测试；
- **尚未执行 `dotnet restore/build/test`**；
- **尚未加载到 Playnite 10 真机**；
- **尚未对真实 Ludusavi JSON 输出做端到端验证**。

## 2. 高级识别功能需要真实数据调优

- Xbox WGS 的目录和文件语义因游戏而异；当前只做候选识别，不自动认定。
- Xbox Game Bar、Windows Screenshots 等公共目录优先依赖文件名匹配；0.4.0 增加无重叠游戏会话时间窗口辅助归类，但仍需要采集真机样本调优时间边界和文件时间语义。
- Epic、Ubisoft、EA、GOG 没有统一的跨游戏截图目录约定。当前支持常见相邻目录和用户自定义来源。
- 外部进程侦测依赖 Playnite 已知 Action、安装目录 EXE 和人工可修正的映射。通用启动器、反作弊和短生命周期 loader 可能需要补规则。
- 0.4.0 已接入未匹配游戏的会话前后文件快照，但扫描根目录、深度、文件类型和阈值仍需真实游戏调优；候选只供人工确认，不应直接当作可恢复规则。

## 3. 多设备冲突尚未形成远端闭环

`DeviceConflictDetector` 已实现保守冲突判定，但当前 Worker 尚未从 Rclone 远端读取其他设备的版本摘要。多设备使用时应：

- 每台电脑写入不同的远端子目录；
- 禁止自动双向恢复；
- 检测到不一致时保留两个版本，由用户选择。

## 4. 恢复是高风险路径

源码实现了 PreRestore、锁定、预览、恢复、校验和回滚状态机，但在完成真实低风险游戏测试前：

- 不启用任何自动恢复；
- 不测试唯一存档；
- 恢复前手动复制原始存档目录；
- Xbox WGS 游戏优先只测备份，不测覆盖恢复。

## 5. 历史差异与保留

- 文件差异依赖 GameSaveCenter 已索引的 manifest；导入的旧 Ludusavi 历史可能没有完整 manifest。
- 分层保留当前只提供“建议保留/候选清理”预览，不自动删除，这是刻意的安全设计。

## 6. 后台通知

手动命令有 UI 状态和错误通知；自动定时/退出任务会写入任务与异常页面。Worker 到 Playnite 的持续事件推送通道尚未完成，因此后台成功通知不是实时主动弹出。

## 7. 主题、材质与宿主边界

- 插件是 Playnite 内嵌 WPF `UserControl`，不能安全控制宿主顶层 HWND，因此不承诺真实 Mica/Acrylic backdrop。
- 0.4.0 支持跟随 Playnite、固定浅色和固定深色；社区主题数量很多，仍需要在多套主题与 100%–200% DPI 下人工验收。
- 毛玻璃采用局部半透明表面与环境光降级方案，不得给大型列表、文字或每一行施加实时 `BlurEffect`。

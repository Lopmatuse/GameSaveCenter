# 已知限制与风险

## 1. 最新 0.6.13 尚未完成全部 Windows/Playnite 业务回归

- 当前 Windows 开发环境已经能够执行 Release 编译和 Core 测试，用户也已确认构建、安装和 Git 推送链路可用。
- 本轮仍未自动操控 Playnite 完成真实 UI、Ludusavi、Rclone、游戏进程和安全软件交互回归，因此不能把“编译通过”等同于“所有业务真机验证完成”。
- 必须继续按 `WINDOWS_TEST_PLAN.md` 保存真实备份、恢复、云端、多主题/DPI 与修改器样本证据。

## 2. 高级识别功能需要真实数据调优

- Xbox WGS 的目录和文件语义因游戏而异；当前只做候选识别，不自动认定。
- Xbox Game Bar、Windows Screenshots 等公共目录优先使用唯一文件名匹配；0.4.1 增加无重叠游戏会话窗口和全局待归类收件箱。仍需采集真机样本调优时间边界、CreationTime/LastWriteTime 语义、超大目录扫描性能和 200 项分批导入体验。
- Epic、Ubisoft、EA、GOG 没有统一的跨游戏截图目录约定。当前支持常见相邻目录和用户自定义来源。
- 外部进程侦测依赖 Playnite 已知 Action、安装目录 EXE 和人工可修正的映射。通用启动器、反作弊和短生命周期 loader 可能需要补规则。
- 0.4.0 已接入未匹配游戏的会话前后文件快照，但扫描根目录、深度、文件类型和阈值仍需真实游戏调优；候选只供人工确认，不应直接当作可恢复规则。

## 3. 多设备远端闭环仍需真实后端验证

`DeviceConflictDetector`、远端 sidecar、隔离下载、哈希/版本校验和受保护恢复向导已经实现；但尚未在两个真实设备和 Rclone 后端完成断线、远端变化及低风险恢复回归。多设备使用时仍应：

- 每台电脑写入不同的远端子目录；
- 禁止自动双向恢复；
- 检测到不一致时保留两个版本，由用户选择。

## 4. 恢复是高风险路径

源码实现了 PreRestore、锁定、预览、恢复、校验和回滚状态机，但在完成真实低风险游戏测试前：

- 不启用任何自动恢复；
- 不测试唯一存档；
- 恢复前手动复制原始存档目录；
- Xbox WGS 游戏优先只测备份，不测覆盖恢复。

## 5. 历史差异与保留

- 文件差异依赖 GameSaveCenter 已索引的 manifest；导入的旧 Ludusavi 历史可能没有完整 manifest。
- 分层保留当前只提供“建议保留/候选清理”预览，不自动删除，这是刻意的安全设计。

## 6. 内嵌录像预览依赖系统编解码器

0.6.12 的 `MediaElement` 使用 Windows Media Foundation。容器扩展名受支持不代表当前机器一定具备对应视频/音频编解码器；内嵌加载失败时仍应使用“打开媒体”交给系统默认播放器。

## 6. 后台通知

手动命令有 UI 状态和错误通知；自动定时/退出任务会写入任务与异常页面。Worker 已提供任务变化信号唤醒的有界长轮询，后台通知接近实时；它仍是可恢复的请求/响应通道，不是无限期双工连接，Worker 重启和管道中断时会回退到 SQLite 快照。

## 7. 主题、材质与宿主边界

- 插件是 Playnite 内嵌 WPF `UserControl`，不能安全控制宿主顶层 HWND，因此不承诺真实 Mica/Acrylic backdrop。
- 0.4.1 延续跟随 Playnite、固定浅色和固定深色；新增媒体收件箱表格与操作区仍需要在多套主题、长文件名和 100%–200% DPI 下人工验收。
- 毛玻璃采用局部半透明表面与环境光降级方案，不得给大型列表、文字或每一行施加实时 `BlurEffect`。
